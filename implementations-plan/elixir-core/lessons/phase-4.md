# Phase 4 lessons — web miner (homelab, 2026-09-04)

- Scaffold: `bunx shadcn@latest init -t vite -b radix -p nova -y -n web-miner --no-monorepo` (the preset prompt is interactive unless `-p` is given). It creates a *nested git repo*, ESLint and Prettier configs and a README — all removed; Biome and the workspace hooks own lint/format. `shadcn add card badge progress separator sonner input label alert` brought the components; the look is the untouched Nova preset (owner: no branding).
- Biome refuses the generated `index.css` (`@custom-variant`, `@theme inline`) until `css.parser.tailwindDirectives = true` in `biome.json`.
- Root `bun test` discovers anything named `*.spec.*` / `*.test.*` across the workspace: the Playwright spec is `e2e/miner.e2e.ts` with `testMatch: /.*\.e2e\.ts$/`, and the Vitest files stay `*.test.ts` (Bun rewrites `vitest` imports to `bun:test`, so they also pass under the root run).
- Playwright's Node loader cannot `require()` the repo's ESM helpers (`scripts/run/registry.ts`: "Cannot require() ES Module … in a cycle"). The hooks are thin wrappers that `execFileSync('bun', ['e2e/run-setup.ts'])`: the Bun script claims a Vite port from the registry with the Playwright pid as owner (long-lived for the run), deploys a throwaway deployment at target 2^127 (`deploy.ts` reads artifacts with `Bun.file`, so it is Bun-only anyway), spawns Vite detached with its output to `e2e/.vite.log`, waits for HTTP 200 and writes `e2e/.run.json`; teardown kills that process group and releases the port.
- Pinned CRS: bb.js 5.2.0 in the browser requests `g1_compressed.dat` bytes `0-16777215` (2^19 points), `g2.dat` and `grumpkin_g1_v2.dat` bytes `0-4194303` from `crs.aztec-cdn.foundation` (fallback `crs.aztec-labs.com`) via global `fetch`, caches the decompressed G1 in IndexedDB (`idb-keyval` keys `g1Data`, `g2Data`, `grumpkinG1DataV2`), and ignores `crsPath`. `crs.lock.json` pins the three sha256 (CDN download and the native bb cache — which bb verified with its chunk hashes on download — agree); `scripts/fetch-crs.ts` materialises `public/crs/` at build time against the lock, and `src/pinned-crs.ts` (first import on the page and in the Worker) wraps `fetch` to answer the CDN hosts from `/crs/<file>` after re-hashing, honouring Range headers. The production CSP's `connect-src` excludes the CDN hosts, so an unintercepted request fails instead of falling back to transport trust.
- Persistence: `AztecIndexedDBStore.open(log, name)` from `@aztec/kv-store/deprecated/indexeddb` for both the PXE and the wallet DB, named per chain id, so a second visit finds its account (`wallet.getAccounts()`) and synced notes. The SQLite-OPFS default needs its worker/WASM assets emitted unhashed (nulo's extension plugin); left for the roadmap.
- Gas: every claim declares `claimGasLimits(node)` (Phase 3 finding); the wallet keeps its estimated teardown limits.
- Gate spelling: `bun run e2e:agent -- bun run --cwd packages/web-miner test:e2e` (the runner takes a command).
- First E2E failure was mine: the `fetch` interceptor built `new URL(input)` without a base, so the page's own relative fetches (`/artifacts/…`) threw "Invalid URL" at boot. Base is `globalThis.location.href` (works in the page and the Worker).
- The lying-node mock must be a *proxy* of the real node that alters only `getPublicStorageAt` results (batched or single): answering every JSON-RPC method with junk fails the client's schema checks before the cross-check runs ("Failed request"), which is the malformed-payload case, not the lying one.
- E2E results (headless Chromium 1234, 11 threads, isolated network, target 2^127): boot (pinned CRS verify + wallet/PXE with persistent IndexedDB + bb.js init) ≈ 15 s; first visit → account → mine → claim proved in-page → balance 4 tELX and `claims 1 / 4` in **38.9 s**; lying cross-check node → "nodes disagree" before any proving, Start disabled (8.8 s); malformed payload → boot error (8.9 s); prover crash mid-job → error shown, restart mines again (33.7 s). 4 passed, 2.0 min. Dev-server pages have no CSP; the production `_headers` CSP is not exercised by the E2E (Cloudflare applies it).
- Not done, on the roadmap: peak browser memory is not recorded by the E2E (Phase 1's spike page measured 2,387 MiB process-tree RSS for the same flow); the SQLite-OPFS store; worker-crash recovery is exercised through a test hook that terminates the Worker (a real crash would surface through `onerror` on the same path).
