- Pinned CRS: bb.js 5.2.0 in the browser requests `g1_compressed.dat` bytes `0-16777215` (2^19 points), `g2.dat` and `grumpkin_g1_v2.dat` bytes `0-4194303` from `crs.aztec-cdn.foundation` (fallback `crs.aztec-labs.com`) via global `fetch`, caches the decompressed G1 in IndexedDB (`idb-keyval` keys `g1Data`, `g2Data`, `grumpkinG1DataV2`), and ignores `crsPath`. `crs.lock.json` pins the three sha256 (CDN download and the native bb cache — which bb verified with its chunk hashes on download — agree); `scripts/fetch-crs.ts` materialises `public/crs/` at build time against the lock, and `src/pinned-crs.ts` (first import on the page and in the Worker) wraps `fetch` to answer the CDN hosts from `/crs/<file>` after re-hashing, honouring Range headers. The production CSP's `connect-src` excludes the CDN hosts, so an unintercepted request fails instead of falling back to transport trust.
- Persistence: `AztecIndexedDBStore.open(log, name)` from `@aztec/kv-store/deprecated/indexeddb` for both the PXE and the wallet DB, named per chain id, so a second visit finds its account (`wallet.getAccounts()`) and synced notes. The SQLite-OPFS default needs its worker/WASM assets emitted unhashed (nulo's extension plugin); left for the roadmap.
- Gas: every claim declares `claimGasLimits(node)` (Phase 3 finding); the wallet keeps its estimated teardown limits.
- Gate spelling: `bun run e2e:agent -- bun run --cwd packages/web-miner test:e2e` (the runner takes a command).
- First E2E failure was mine: the `fetch` interceptor built `new URL(input)` without a base, so the page's own relative fetches (`/artifacts/…`) threw "Invalid URL" at boot. Base is `globalThis.location.href` (works in the page and the Worker).

## A3 codex audit, round 1 (session `01a06a0b-5c3c-79e0-b066-ec539cf5b950`, xhigh, fresh)

Verdict "reject pending fixes" — no reward-redirection path in honest code, eight material findings, all applied:

- **CRS cache bypass**: bb.js reads `g1Data` / `g2Data` / `grumpkinG1DataV2` from its idb-keyval cache *before* fetching, so the pins only governed a cold cache. Both the page (before the wallet's prover) and the Worker (before `Barretenberg.new`) now `purgeCrsCache()` (`delMany` of those keys); every load goes through the interceptor and bb.js re-caches the decompressed form of verified bytes. E2E: a 32 MiB all-zero `g1Data` planted via `addInitScript` before the page runs, then a full mine → claim.
- **CSP**: `https://*.aztec-labs.com` admitted the fallback CRS host `crs.aztec-labs.com`; `connect-src` is now the exact testnet RPC origin (a custom node needs a `_headers` edit — documented). The dev/preview servers now serve the headers parsed from `public/_headers`, `connect-src` widened only by `http://127.0.0.1:* http://localhost:*`, so the E2E runs under the production policy and the CDN is blocked there too.
- **Epoch hand-off**: the reducer emitted `mine` without `halt` and the Worker refused a second job while busy ("already mining" → failed). Now `epoch` → `[halt, mine]`, and the Worker queues one replacement job that starts when the running loop exits; the controller no longer re-issues jobs on `stopped`.
- **Crash recovery**: `onerror` only reported. The controller now owns Worker generations: `onerror` or a Worker-reported init/run error terminates and replaces the Worker; late messages from a superseded generation are ignored; `ready()` rejects on an init error instead of pending forever. The E2E hook posts a `crash` message that makes the Worker throw, so the test exercises the real `onerror` path.
- **Refresh races**: refreshes are serialised through a promise chain and an older `open_epoch` never overwrites a newer one.
- **Store namespace**: PXE and wallet stores are keyed by L1 chain id, rollup version and rollup address, not the L1 chain alone.
- **Soak**: hours capped at 2 in the script; send timeouts bounded by the remaining time; "closed epochs" read from chain each loop (whoever closed them); each row carries the run id and the miner address, and the default report path includes the start timestamp.
- **Deploy record**: after `bind_token` the script reads back `constants()`, epoch 0 and the token's minter and refuses to write a record that disagrees with the generated params.
- Nits applied: past epoch secrets are dropped on every new job; the page states a compromised host could redirect claims or spend the wallet, not merely read; `contracts.yml` builds the production web bundle (the only job with compiled artifacts); the E2E reloads the page and claims again with the persisted account. Noted, not changed: at 1.6 s native proofs the 2^124 initial target closes an epoch in ≈ 2 min rather than 5 — the retarget's job, observed live in the soak.

## A3 codex audit, round 2

Four new material findings, applied: (1) a Worker that failed *before* ever becoming ready was replaced with one that would fail identically, forever — init failures now abandon the prover with a message, runtime crashes are replaced at most three times in a row; (2) the production CSP admits only the default node while the Network card accepts any URL — the build carries `VITE_ALLOWED_NODE_ORIGINS`, boot refuses a node outside it with a message naming the file to edit (dev builds also accept local nodes), the card states the list, and `src/csp.test.ts` keeps `_headers` and `.env.production` in lockstep (exact `connect-src`, no wildcards, no CRS hosts); (3) the soak rotated its account one winner too late — now immediately after a public revert; (4) the soak report scopes rows to the deployment, names the runs, and limits epochs to the soak's window. Nits applied: full rollup address in store names; web-miner changes trigger the contracts workflow (the production build lives there); the E2E records the browser's peak process-tree RSS (Playwright's Chromium found by its temporary profile directory). Codex's read on the reverted-claim finding: do not mutate the PXE's tagging store (its finality guard exists for reorgs); the no-fork contract alternative is the standard token's `initialize_transfer_commitment` + public `mint_to_commitment`, which avoids constrained delivery at the cost of a redeploy and a privacy-footprint review — on the roadmap.

## A3 codex audit, round 3

Three material findings, applied: the crash counter reset on every successful respawn, so the cap could never be reached — it now counts per page lifetime and abandonment is terminal (`prover-dead` in the reducer, Start disabled, tested); the soak report accepted rows without a deployment stamp and could count epochs that closed after the window — rows must match the deployment (`--legacy-ok` admits the pre-stamp rows of this soak's first two miners and says so in the report), the active epoch at the start is found with `findLastIndex`, and a close counts only if it falls inside the window; `--hours NaN` disabled the 2 h cap — numeric options must be finite and positive. Nits: the boot error names both `.env.production` and `public/_headers`; the hand-off no longer claims Phase 5 complete before it is.

- Serving the production CSP from the dev server found two things the production `_headers` alone would have hidden: (1) Vite's React plugin injects an inline preamble script, so the *dev* policy needs `script-src 'unsafe-inline'` (the built bundle has no inline scripts; production keeps `'self' 'wasm-unsafe-eval'`); (2) bb.js loads its WASM by `fetch`ing a `data:` URI, which `connect-src` blocks unless it lists `data:` — every node call then fails with "Failed to fetch" because the wallet's prover never initialises. `connect-src 'self' data: <node origin>` is the production value; `data:` cannot exfiltrate.
- Peak browser memory (E2E test 1, headless Chromium, 11 threads: boot + W proving + two in-page claims with a reload between): **3,047 MiB** process-tree RSS (Phase 1's single-claim spike page: 2,387 MiB). On the roadmap: the SQLite-OPFS store.
