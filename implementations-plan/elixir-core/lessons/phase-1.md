## Item 2 — proof-layout manifest and mutation tests

- bb's CLI never prints a transcript manifest (`use_manifest` is test-only), so the layout is derived from source at the pinned version: `honk/proof_length.hpp` (Oink 8 commitments; Sumcheck `log_n × 8` univariates + 41 evaluations; Shplemini 24 folds + 25 evals + Q + W = 402) **plus** the IO pairing-point block bb keeps at the head of the exported proof (`bbapi_ultra_honk.cpp`: only the inner public inputs are split off; `public_inputs_type.hpp`: 2 BIGGROUP points × 4 = 8 fields) = 410. Verified empirically with `scripts/proof-shape.ts` (limb widths ≤ 17 bytes vs full scalars; the two lookup commitments and `LOOKUP_INVERSES` are zero for W since it has no lookups; padded sumcheck rounds 18–24 show `S(1) = 0`).
- Manifest phases: io 0..7, oink 8..39, sumcheck_univariates 40..239, sumcheck_evaluations 240..280, gemini_folds 281..376, gemini_evals 377..401, shplonk 402..405, kzg 406..409. sha256 `2c913f7e…f6c3`, pinned by `src/proof-layout.test.ts`.
- Note for §3.3: the 8 IO fields are pairing inputs. Natively a flip fails `bb verify`; in the recursive path they are *aggregated* into the outer circuit's pairing points and enforced at the decider/tube (Fact 19), i.e. later, not in the app circuit. Item 3's per-phase tamper test on the real tx covers this.
- Mutation results (native, fixture proof of `elixir_work`): 410 single lowest-bit flips → 0 survive (12 s); 50 random 2–8-field combinations with random bit positions → 0 survive; nonce ±1 in public inputs → fails; VK of `sweep_1024` → fails; ZK-flavour proof (`-t noir-recursive`, 458 fields) against the non-ZK verifier target → fails with W_VK and even with its own ZK VK.

## Item 5 — CRS integrity (I9)

- bb 5.2.0 pins the BN254 CRS: `srs/factories/bn254_crs_data.hpp` carries the first two G1 points, the 128-byte G2 point and its SHA-256, and per-chunk SHA-256 hashes of the G1 file (`BN254_G1_CHUNK_HASHES`); `get_bn254_crs.cpp::verify_bn254_crs_integrity` checks them. It runs on the native download path (plain HTTP, line 190) and on cache loads only with `BB_VERIFY_CRS=1` (or `bb verify-crs`).
- bb.js (`crs/net_crs.js`) fetches `g1_compressed.dat`/`g2.dat` from `crs.aztec-cdn.foundation` (fallback `crs.aztec-labs.com`) over HTTPS with no hash check; the C++ comment for the WASM path (`bbapi::SrsInitSrs`) says it "receives bytes that bb.js fetched over HTTPS". So the miner's browser path relies on transport security alone. I9 is **partially true**: native yes-on-download, WASM no. Mitigation for Phase 4: the web miner fetches the CRS bytes itself, hashes them against the pinned chunk hashes (they are public constants in bb) and only then hands them to bb.js — or bundles a pinned CRS.

## Item 4 — ticket-cost measurements

- (a) Early abort: the ticket hashes all 410 fields including `KZG:W`, the last transcript entry, so the digest is computable only when `construct_proof` returns; from `bb prove --bench_out` (median of 5 native proves of `elixir_work`) that is 100 % of the prove and 94.9 % of the `bb prove` wall clock (the rest is I/O and serialisation). GO ≥ 90 % ✓.
- (b) Same-witness re-derivation through the 4 disabled sumcheck rows (Fact 17). Codex consult (gpt-5.6-sol xhigh, session `01a068b5-458e-75f3-bd59-3b1a1d28a811`; a first attempt phrased as an "attack" was refused by codex's cyber filter, rephrased as proving-cost accounting): verified against source — the grand product starts at `gp_start = TRACE_OFFSET` (`honk/library/grand_product_library.hpp:96`), so rows 0–3 do not enter `z_perm` directly, but `beta, gamma` are sampled after the wire commitments (`oink_prover.cpp:40,163`), so any change to a wire commitment re-randomises `z_perm`, sumcheck (`alpha`, gate challenges) and the whole PCS (fresh `u`, `rho`). Skippable: witness generation, trace construction, the wire MSMs (replaced by sparse commitment deltas); the w_4/lookup block only if no RAM/ROM records. No stock bb CLI/bbapi path resumes a prover mid-way (`bbapi_ultra_honk.cpp:68` is one-shot), so an executed re-derivation needs a patched C++ build (clang absent here; gcc 15 builds are unsupported upstream). Decision: report the timer-derived figure, clearly labelled, and leave the executed re-derivation as a follow-up for the owner. Phase shares (5-run medians, `scripts/ticket-cost.ts`): create_circuit 11.7 %, ProverInstance 4.4 %, commit_to_wires 21.4 %, w_4/lookup commits 8.3 %, z_perm 11.4 %, sumcheck 6.5 %, PCS 36.6 %. Must-redo ≥ 62.4 % (54.1 % if the w_4/lookup block is also skipped). GO ≥ 50 % ✓ on the estimate. Wording adopted from codex: "an attacker-favourable implementation estimate from honest-prover phase timers, not a cryptographic lower bound for an optimised incremental prover".

## Item 3 — spike contract and the real claim

- aztec-nr 5.2.0 idioms that cost a compile each: `#[internal("private")]` is an inlined helper (same circuit), the separate-circuit variant is `#[only_self] #[external("private")]` called via `self.call(Self::at(self.context.this_address()).f(..))`; free functions cannot live inside the `contract` block (move them to a module); view return types need `Serialize` + `Deserialize` derives; `linter`-style import of `internal` must be explicit. `aztec-nargo compile` alone leaves public bytecode untranspiled — the wallet rejects the artifact ("Contract's public bytecode has not been transpiled"); use `aztec compile --workspace` (also writes the Chonk VKs).
- aztec.js 5.2.0 shapes: `.send({ from, fee, wait })` on a deploy resolves to `{ contract, instance, receipt }`; on a method it resolves at runtime to `{ receipt, offchainEffects, offchainMessages }` although the type says `TxReceipt`; `.simulate()` resolves to `{ result, offchainEffects, offchainMessages }`. Accounts: `createSchnorrInitializerlessAccount(secret, salt, deriveMasterMessageSigningSecretKey(secret))` needs no deploy tx and can pay through the sponsored FPC immediately (`getContractInstanceFromInstantiationParams(SponsoredFPCContract.artifact, { salt: SPONSORED_FPC_SALT })` + `wallet.registerContract`).
- Testing invalid proofs on the real stack: the digest is a coin flip against the target, so a tampered proof must be *chosen* to still win (iterate bit/slot) or the run measures the target assert instead of the verifier. Wrong `out` and replay must be tested before the valid claim, since the nullifier is Poseidon2(digest) and a consumed digest fails at the AVM nullifier check, not at the verifier.
- bb's `vinfo` lines ("Num rows in the ECCVM") need `BB_VERBOSE=1` in the environment of the process that spawns bb; `LOG_LEVEL=verbose` alone only surfaces bb's `info` lines through the pxe:prover logger.
- Vite + Bun isolated linker do not mix: Vite's pre-bundler resolves the aztec packages' transitive imports (zod, pino, @aztec/protocol-contracts, @aztec/noir-acvm_js) from the app root. Switched `bunfig.toml` to `linker = "hoisted"` (my-stack's documented escape hatch). vite-plugin-node-polyfills' shim ids then need an absolute path from the plugin's own package.
- Playwright 1.62 exposes no `browser.process()`; a persistent context's user-data-dir on the Chromium command line identifies the process tree for RSS sampling.

## Item 3 (browser) — what it took to prove and claim inside headless Chromium

- Owner pointer to `~/Projects/nulo` (apps/tools + apps/extension vite configs) settled the Vite setup: exclude only the WASM bindings (`@aztec/bb.js`, `@aztec/noir-acvm_js`, `@aztec/noir-noirc_abi`, `@aztec/noir-noir_js`) from pre-bundling, `dedupe` the two bindings, `nodePolyfills({ globals: { Buffer, global, process } })`, and alias `detect-node` to `export default false` so pino keeps its browser transport. Excluding more `@aztec/*` packages cascades: anything that imports `@aztec/foundation` then serves foundation from source and its CommonJS deps (`sha3`, `msgpackr` via kv-store's `#msgpackr` → `msgpackr/index-no-eval`) lose their named exports. The CJS deps of the excluded packages are listed as `'@aztec/bb.js > comlink'`-style includes.
- The embedded wallet's default SQLite-OPFS store spawns a worker via `new URL('./worker.js', import.meta.url)` inside `@aztec/kv-store`; under dependency pre-bundling that URL points into the `.vite/deps` chunk and the worker crashes ("SQLite worker crashed: undefined"). The spike passes `openTmpStore(true)` from `@aztec/kv-store/deprecated/indexeddb` as both `pxe.store` and `walletDb.store`. The web miner must ship the OPFS assets explicitly (nulo's extension emits `sqlite3.wasm` and `sqlite3-opfs-async-proxy.js` unhashed) or keep IndexedDB.
- `server.fs.allow` must include the repo root: the hoisted `node_modules` holds the WASM binaries served through `/@fs/`; otherwise the ACVM WASM fetch is a 403 and `WebAssembly.compile` fails with "HTTP status code is not ok".
- `Contract.at(address, artifact, wallet)` is not enough for a fresh wallet to *use* a contract: register the instance fetched from the node (`aztecNode.getContract(address)`) with `wallet.registerContract(instance, artifact)`, or simulation fails with "No contract instance found".
- Playwright 1.62 needs its own Chromium (`bunx playwright install chromium` → chromium-1234); `browser.process()` is gone, so the process tree for RSS sampling is found through the persistent context's user-data-dir on the command line. Vite's stdout pipe must be drained or the dev server stalls once the pipe fills.
- Numbers (Chromium 151 headless shell, 11 threads): wallet + PXE boot 5.9 s; bb.js init incl. CRS download 20.5 s; W proof 3.2–3.4 s (Bun's WASM runtime: 6.3 s); claim proved in-page and mined in 21.9 s; peak Chromium process-tree RSS 2,387 MiB.
