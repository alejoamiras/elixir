# Phase 3 lessons — miner-core (homelab, 2026-09-03)

- Package shape per plan §3.5: `proof.ts` (fields → ticket, domain separators), `retarget.ts` (mirror + seed), `work.ts` (`WorkProver` interface, `BbJsWorkProver` = noir_js execute + UltraHonkBackend non-ZK), `epoch.ts` (open epoch / params / claims / rules via `simulate`, unwrapping `{ result }`), `claim.ts` (interaction builder), `secret.ts` (per-epoch random `Fr`), `miner.ts` (`mineEpoch` loop with an `onAttempt` stop hook). Compiled artifacts stay build outputs resolved from the sibling packages (`artifacts.ts`), not committed copies (the miner artifact is 1.9 MB).
- `bun run e2e:agent -- <cmd>` ran nothing and exited 0: bun consumes the `--` after the script name, so the runner's `argv.indexOf('--')` never matched. It now treats every remaining argument as the command and refuses an empty one. The plan's gate spelling `e2e:agent -- miner-core` maps to `bun run e2e:agent -- bun test packages/miner-core`.
- 5.2.0 API: `AztecAddress.fromString` does not exist (`fromStringUnsafe`), same as in the browser page. A claim tx carries two note hashes, the minted UintNote plus one from the sponsored-fee path, so the public-effects test asserts ≥ 1 and that neither the recipient nor the secret appears anywhere in the effect.
- A wallet must know a deployment's *token* instance too (the claim calls `mint_to_private`); forgetting it produced "No contract instance found" for every burst claim and made the cross-deployment test pass for the wrong reason. `registerDeployment` now registers both, and the cross-deployment rejection is asserted to come from the verifier (`/verif|proof/`).
- One embedded wallet cannot simulate several of its own claims concurrently: `Promise.all` over 8 sends failed 7 with "Cannot find the leaf for nullifier …". Submitted sequentially: 4 accepted, 4 refused at *simulation* with "epoch is not open" (the anchor-block `open_epoch` assert), i.e. doomed claims cost the miner nothing after the close lands; 40 s for the 8 submissions on this box. The public-side "stale claim" revert (fee paid) needs a claim anchored before the close but sequenced after it, which one wallet cannot force; left for the testnet soak's natural races.
- Live results (isolated local network, easy target 2^127): claim → private balance = 4 tELX; tampered field → "Failed to verify the generated proof!"; replay → nullifier collision; cross-deployment proof → verifier failure; burst as above. Suite wall clock ≈ 4 min after the ~1.5 min node boot.
