# Phase 3 lessons — miner-core (homelab, 2026-09-03)

- Package shape per plan §3.5: `proof.ts` (fields → ticket, domain separators), `retarget.ts` (mirror + seed), `work.ts` (`WorkProver` interface, `BbJsWorkProver` = noir_js execute + UltraHonkBackend non-ZK), `epoch.ts` (open epoch / params / claims / rules via `simulate`, unwrapping `{ result }`), `claim.ts` (interaction builder), `secret.ts` (per-epoch random `Fr`), `miner.ts` (`mineEpoch` loop with an `onAttempt` stop hook). Compiled artifacts stay build outputs resolved from the sibling packages (`artifacts.ts`), not committed copies (the miner artifact is 1.9 MB).
- `bun run e2e:agent -- <cmd>` ran nothing and exited 0: bun consumes the `--` after the script name, so the runner's `argv.indexOf('--')` never matched. It now treats every remaining argument as the command and refuses an empty one. The plan's gate spelling `e2e:agent -- miner-core` maps to `bun run e2e:agent -- bun test packages/miner-core`.
- 5.2.0 API: `AztecAddress.fromString` does not exist (`fromStringUnsafe`), same as in the browser page. A claim tx carries two note hashes, the minted UintNote plus one from the sponsored-fee path, so the public-effects test asserts ≥ 1 and that neither the recipient nor the secret appears anywhere in the effect.
- A wallet must know a deployment's *token* instance too (the claim calls `mint_to_private`); forgetting it produced "No contract instance found" for every burst claim and made the cross-deployment test pass for the wrong reason. `registerDeployment` now registers both, and the cross-deployment rejection is asserted to come from the verifier (`/verif|proof/`).
- One embedded wallet cannot simulate several of its own claims concurrently: `Promise.all` over 8 sends failed 7 with "Cannot find the leaf for nullifier …". Submitted sequentially: 4 accepted, 4 refused at *simulation* with "epoch is not open" (the anchor-block `open_epoch` assert), i.e. doomed claims cost the miner nothing after the close lands; 40 s for the 8 submissions on this box. The public-side "stale claim" revert (fee paid) needs a claim anchored before the close but sequenced after it, which one wallet cannot force; left for the testnet soak's natural races.
- Live results (isolated local network, easy target 2^127): claim → private balance = 4 tELX; tampered field → "Failed to verify the generated proof!"; replay → nullifier collision; cross-deployment proof → verifier failure; burst as above. Suite wall clock ≈ 4 min after the ~1.5 min node boot.

## A2 codex audit, round 1 (session `01a06974-a91d-7a73-a2ff-05379348f972`, xhigh)

Ten findings, all applied:

- `secret.ts` used `Fr.random()` blindly → now 64 CSPRNG bytes reduced with `Fr.fromBufferReduce` (uniform in the field).
- `retarget.nr`: the hint constraint is its own `pub fn constrain_quotient` so malicious hints can be tested directly: off-by-one quotient, unreduced remainder (`q − 1, r + d`), and the wrapped pair `q = −1, r = product + d` (only the range checks reject it). Plus a 2^126 case where the product exists only in the field.
- Simulator: from the configured 2^122 a ÷100 collapse saturates the target at 2^128 − 1 — the chain stays live (every proof wins) but the cadence floor is N / H, so the "recovers within 5 epochs" claim only holds with headroom (asserted separately at 2^118).
- Same-block roll + claim: **the TXE applies public writes immediately**, so the claim fails its historical read ("epoch is not open") instead of reaching `record_claim`'s "stale claim". The race codex wanted (private anchored before the close, sequenced after) is only reproducible on a network; the test is named for what TXE shows and the burst test covers the real path.
- `epoch.ts` re-reads `open_epoch` after the three simulations and retries if it moved; `miner.ts` calls `onAttempt` before returning a winner so a caller that switched epochs can veto it.
- `deploy.ts` records `new URL(nodeUrl).origin` only (provider keys live in URL paths) and refuses to overwrite `deployments/<profile>.json` unless `ELIXIR_DEPLOY_FORCE=1`.
- CI: `elixir.params.json` and `scripts/params-codegen.ts` are in the contracts / work-circuit / miner-core filters; contracts.yml runs `bun run codegen && git diff --exit-code` before compiling.
- Live suite: the public-effects test now asserts the siloed ticket nullifier (`siloNullifier(miner, Poseidon2(DOM_NULL, digest))`) and public-data values equal to the digest and to REWARD; the burst uses one ephemeral wallet per winner (2N wallets, each registering FPC + miner + token) submitting concurrently with `dontThrowOnRevert`, classified by `executionResult`, logging fees and latency.
- Narrative headers dropped from `main.nr`, `claim.ts`, `miner.ts`, `work.ts`, `live.test.ts`.
- **The concurrent burst found a real defect the sequential one hid: the closing claim always reverted.** Per-tx receipts: successes in blocks 11, 12, 13 (count 3), then every later claim reverted — including the first tx of block 14 — and the epoch stayed open with 3 claims. Reverted txs paid exactly their gas *limit* (3 241 248 021 000 000 vs 2 946 586 005 000 000 used by a success). Cause: the wallet estimates gas limits from a simulation at send time, when the count was < N − 1, so the limits cover a plain `record_claim` but not the Nth one, which also retargets and initializes the next epoch; whichever claim lands as the closer runs out of gas, reverts, pays, and leaves the count at N − 1 for the next victim. Sequential submission never hit it because each simulation saw the true count. Fix in miner-core: `claimGasLimits(node)` returns the network's per-tx maximum (`nodeInfo.txsLimits.gas`) and every claim declares it (`fee.gasSettings.gasLimits`); a successful tx pays for gas used, so the only cost is the up-front fee limit, which the sponsored FPC absorbs. The web miner must do the same. With the limits declared, the concurrent burst behaves: 4 accepted (blocks 11–12; the closer used 3 697 470 018 000 000, about 25 % more than a plain claim), epoch 0 closed with 4 claims, epoch 1 open, and the other 4 reverted *in public* as stale at 2 571 799 774 500 000 each — cheaper than a success, because they revert at the first assert of `record_claim` and pay only for gas used. Mined receipts carry no revert reason in 5.2.0, so the test classifies a mined revert after the close as stale and a pre-send refusal by its "epoch is not open" message. 137 s wall for 8 concurrent claims (client proving 57–136 s each on this box).
- `tmux kill-session` on a running `e2e:agent` kills the runner but not the node and anvil it spawned (they live in their own process groups, by design), so the runner's teardown never runs and the pair lingers for hours holding ~1 GB. Found by `ps` (data dir under this worktree's `.localnet/`), killed by pgid. Stop a live run by interrupting the runner (Ctrl-C in the pane), not by killing the session.
