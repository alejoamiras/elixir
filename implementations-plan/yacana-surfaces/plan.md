# yacana-surfaces

Rename Elixir to Yacana, then build the three product surfaces of the v3 interface studies on one Cloudflare Pages origin as monorepo packages, quality-driven: `packages/ui` (tokens, fonts, signature components), the `packages/web-miner` redesign (M1 cockpit, passkey-first keys with the twelve words behind a link, a key vault whose default mode keeps no spend secret at rest, indexed accounts for rotation, private/public withdraw, power slider, the win beats and failure states, settings, a phone stop-screen), `packages/web-stats` (Observatory + Verify, reading the node from the browser, no server), `packages/web-landing` (H3 hero, Money section, the demo proof in-page, launch mode) and `packages/site` (config, assembly, headers, deploy). Every phase is gated by lint + typecheck plus the unit, component and isolated-network Playwright layers it touches; five stacked PRs, opened only after the codex loops converge.

Design source of truth: the v3 interface studies binder (a Claude Artifact; source `yacana-ux-v2.html` in the session scratchpad). Recon: `recon.md`. Drafts: `drafts/{main,codex,fable}-plan.md`. Audits: `audit-codex.md`, `audit-fable.md`. ELI5: the Artifact linked under Seeds.

## Decisions already made by the owner (not reopened here)

Tier `deep`; `code_review: off`; validation layers lint + typecheck + bun:test, Vitest, Playwright on the isolated network (no live-testnet CI gate); full rename now including a fresh testnet deployment (the agent runs it with the deployer secret supplied through the environment, never printed); no indexer and no scheduled rebuild (the browser reads the node); **Cloudflare Pages Git integration builds production from `main` and a preview for every other branch** (no Cloudflare token in GitHub); one origin, **`yacana.network`** (bought, zone on Cloudflare) with `/`, `/mine`, `/stats`, `/verify`, passkeys bound to that hostname; a key is a passkey or twelve words, never both, and **no 24-word backup of a passkey key**; **one account per key, no rotation** (a lost race is recovered by resetting the key's local chain view); no cross-check node; English only; `/harden security` recommended before mainnet, not scheduled here.

### Critical paths

**Passkey → account.** Preflight runs isolation, CRS, node and `assertDeployment` first, then shows the key screen. On the click, before any aztec import: `createPasskey` (rp.id = `VITE_RP_ID`, `residentKey: 'required'`, `userVerification: 'required'`, ES256 + RS256, `extensions.prf.eval.first = sha256('yacana.passkey.prf.v1')`, create→get fallback when `prf.enabled` but no result; if the authenticator returns no PRF at all the screen offers the twelve words) → `masterFromPrf` → `deriveAccountFields(master, 0)` → the wallet import → `openWallet` + `registerAccount` (re-registration is idempotent) → `MasterRecord`. Passkey keys default to **ask every open**: nothing is stored but the record's metadata (method, credential id, the derived address), and every open is one touch (`assertPasskey({ allow: [credentialId] })` on the click of "Open"; "resume mining when the page opens" resumes after that touch). In every mode, every open re-derives index 0 and fails closed unless it equals the stored address. The convenience mode ("stay open on this device") seals the master with the device key instead; switching back deletes the ciphertext (tested). Words keys always seal the master (no PRF to re-derive from). "I already have a key" = discoverable `assertPasskey` without `allow`; the derived address is matched against records, or a new record is created. Host rules: the production alias `yacana.pages.dev` redirects to `yacana.network`; Cloudflare preview hosts (`<branch>.yacana.pages.dev`) show a "preview" banner and disable key creation and restore; E2E `localhost` is exempt; nothing creates keys off `yacana.network`. A passkey key has no backup by design (owner's decision): the key screen says so, and the wallet nudges to move funds off a key that holds more than a session's worth; the decision is revisited before mainnet.

**Twelve words.** `generateMnemonic(english, 128)` → grid → the checkbox hides the words (dots in the DOM, not CSS blur) → quiz on words 3/7/11 with paste blocked, blur on tab hide and after 60 s → `masterFromMnemonic` → the same path; `backedUp` flips when the quiz passes. Restore: link → hostname banner → textarea (`autocomplete="off" autocorrect="off" spellcheck="false"`, paste allowed, drag-drop blocked, no `navigator.clipboard.readText`, state cleared on unmount) → `validateMnemonic` → derive → open.

**Lost race recovery.** A claim classified `reverted` or `delivery-blocked` means the PXE advanced a sender tag index for a note that never landed and will not reconcile it until the transaction is FINALIZED on L1 (tens of minutes; `node_modules/@aztec/pxe/dest/tagging/sender_sync/*`). The miner recovers by **resetting the key's local chain view**: `resetAccountView` deletes the PXE namespace, reopens it, re-registers the account and re-syncs from chain; the reverted send is not in the chain's logs, so the fresh sync never learns of it, and the notes come back the way a new device recovers them. Copy: "You lost a race with another miner. Re-syncing this key from the chain…". The honest pause ("this key can claim again in ~N min") is the fallback if a reset does not unblock (an inference verified by the P2.5 E2E). No second account, no rotation (owner's decision); rotation and discovery stay out of scope, and `deriveAccountFields` keeps its index parameter for a later plan. Residual, stated in the docs: one device per key at a time (two PXEs on the same account desync their delivery indexes).

**Mine → win → claim → mint.** Worker `attempt{ score, proveMs }` → reducer (ledger line, best of epoch, rate) → ScoreLoop dot. On a winner the dot rises 420 ms and the bar flashes 900 ms while the claim is built; the loop header becomes the Stepper: `proving` (elapsed) → `sent` (TTL countdown to `expiresAt`) → `waiting` → `minted`: the receipt's tx effect supplies the chips, labelled as this transaction's effects (the claim's nullifier and the mint's note hash are its only application effects; indices verified in P2.5), `claims k → k+1`, balance count-up 600 ms, the marks stay until the next attempt, `start()` resumes. Failures go through `classifyClaimFailure`: `reverted` / `delivery-blocked` → "claim reverted" + `pausedUntil` + the fresh-key button; `expired` → "claim expired" (mining continues); `other` → the ✗ line. OS notifications carry no amounts.

**Stats read path.** Shell renders → `assertDeployment` → `readOpenEpochNumber` (fixed slot) → the slot chunk(s) for `[open − 47, open]` (one 66 KB fetch, `slots/<chunk>.json`) → `readEpochs` (three `getPublicStorageAt` per epoch, eight in flight, 10 s timeouts, ≤ 96 epochs per read) → `readTotalSupply`, `readGenesis`, `readLottery` → tiles, strip, charts, table render as batches land; "load older" reads the previous 48; the 30 s poll re-reads `open_epoch`, the open row and `total_supply`. Selection ↔ `?epoch=N` (`history.replaceState`, `popstate`); ← → step within loaded rows and trigger "load older" at the left edge. No block scanning: "last claim" shows the open epoch's claims count and age, not a timestamp. The landing's live strip reads only the open row, `total_supply` and the last 12 epochs (≈ 40 reads), polls every 60 s, and shows an unreachable state instead of retrying hard.

**Landing demo.** Click (desktop only) → `new Worker(new URL('../../web-miner/src/demo/demo.worker.ts', import.meta.url), { type: 'module' })` → `prove-once` with the live seed/epoch/target from the reader, `threads = max(1, min(4, cores − 1))` → steps with real ms → score, the bar, odds `1 in ⌈difficulty⌉`; the dot joins the loop; the proof and the secret are discarded; the Worker is terminated in `finally` and after a 90 s timeout. Nothing leaves the page. An E2E asserts no `barretenberg*` chunk loads before the click.

### Non-obvious mechanics

- **One origin.** `assemble.ts` builds the landing (`base /`), the miner (`--base /mine/`) and the stats (`--base /stats/`) into `packages/site/dist/{,mine,stats}` (E2E runs assemble into `packages/site/e2e/.dist`), materialises `crs/`, `artifacts/` and `slots/` once at the root, renders `_headers` (one `/*` block: COOP `same-origin`, COEP `require-corp`, CORP `same-origin`, CSP `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; script-src-attr 'none'; worker-src 'self' blob:; connect-src 'self' data: <node>; img-src 'self' data:; style-src 'self' 'unsafe-inline'; font-src 'self'; frame-src 'none'; frame-ancestors 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`, `Permissions-Policy` (camera, microphone, geolocation, payment off), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`), `_redirects` (`/mine/* /mine/index.html 200`, `/stats/* /stats/index.html 200`, `/verify /stats/index.html 200`) and `dist/build.json` (mode, commit, node origins, RP ID). In production mode `assemble.ts` fails when `VITE_E2E_QUERY_OVERRIDES` is set, when any origin is `localhost`/an IP/non-HTTPS, or when the RP ID differs from `site.env`. Cloudflare's Git build runs `bun install --frozen-lockfile && bun run site:build` in production mode with no secrets (the `VITE_*` values come from the committed `site.env`), so `build.json` always says `production` there; a local build with the E2E flag lands in `e2e/.dist` and can never be what Cloudflare serves. `packages/site/wrangler.jsonc` (`name: yacana`, `pages_build_output_dir: dist`) is the project definition Cloudflare reads. Standalone dev/preview servers keep `base /`, materialise CRS, artifacts and slots into their own gitignored `public/`, and `vite-base.ts` injects the same rendered headers so dev, preview and production run under one policy from P2.1 on. E2E servers bind `localhost`, not `127.0.0.1` (WebAuthn's RP ID must be a domain; P2.1 spikes both and records the result), and E2E builds set `VITE_RP_ID=localhost`.
- **Key storage.** Spend authority is `secret` + `signingKey`. The embedded wallet's `WalletDB` writes `sk`, `salt` and `signingKey` to its store (`node_modules/@aztec/wallets/dest/embedded/wallet_db.js:24-31`), so it gets an in-memory `AztecAsyncKVStore` (`wallet/memory-store.ts`: a full `AztecAsyncMap` plus `close`, run against `@aztec/kv-store`'s `map_test_suite` and a WalletDB-shaped lifecycle test) and accounts are re-registered from the vault on every open (`embedded_wallet.js:305-306` makes it idempotent). What is at rest: for a passkey key in the default mode, only the record's metadata (the master is re-derived from the PRF on every open); for a words key, or a passkey key in convenience mode, the AES-GCM-sealed 32-byte master under a non-extractable `CryptoKey` in the same IndexedDB. Honest limit, stated on the page and in the threat model: the browser serialises that key to the profile too, so against a stolen unencrypted disk the sealed mode is plaintext-equivalent (it defends against greps and copied databases, not forensics); the default passkey mode is the one with no spend secret at rest. The PXE store stays persistent and unencrypted: it holds the four privacy secret keys (viewing, tagging, nullifier-hiding) and notes — balance readable from disk, not spendable; sqlite-opfs encryption stays a roadmap item. Forgetting a key requires typing its address's last four characters and removes the master record; the PXE namespace is shared, so "forget everything on this device" deletes it and re-syncs nothing. **No legacy migration**: the production origin is new and receives its first deploy only at P4.2, so no `elixir-*` or interim `yacana-wallet-*` database can exist there; boot refuses to continue if an unexpected `yacana-wallet-*` database is found (developer hygiene), and never deletes anything unasked.
- **PRF ceremony ordering.** `navigator.credentials.*` is the first await after the click; CRS and node preflight finish before the key screen; the wallet import starts after the ceremony resolves (a consumed user gesture makes WebAuthn throw `NotAllowedError`).
- **Slot table.** `deriveStorageSlotInMap` is Poseidon2 through bb.js WASM (~3 MB gzipped; `node_modules/@aztec/foundation/dest/crypto/poseidon/index.js:5-12`). The map slots for `epochs[e]` and `claims[e]` depend only on `e` and the storage layout, so `gen-slots.ts` (Bun) emits `slots/<chunk>.json` (512 epochs, ~66 KB) for `e < 262,144` at build time (≈ 2.5 years of testnet, ≈ 30 years of mainnet; a build constant); the browser fetches the chunk its window needs. Fixed slots (`open_epoch`, `genesis`, `token`, `launch_mix`, `launch_reveals`, the token's `total_supply`) come straight from the artifacts' `storageLayout`. The read path of stats and landing ships no WASM (the landing's only WASM is the click-gated demo chunk; an E2E asserts it). Beyond the table, or when a chunk fails to load, the page shows "history unavailable beyond epoch N" and keeps the tiles that need no map slot. The generator is pinned by a bun:test against `deriveStorageSlotInMap` for two chunks. No lazy bb.js fallback (it would drag the prover pipeline into stats).
- **Power slider → threads.** threads ∈ [1, cores − 1]; labels eco = ⌈(cores − 1)/4⌉, balanced = ⌈(cores − 1)/2⌉, max = cores − 1; `reconfigure` finishes the proof in flight, destroys and recreates `Barretenberg`, resumes from `nextNonce` with the same secret; the P2.2 E2E wraps three reconfigures in the existing `rssWatcher` and fails on growth above 300 MiB, in which case the fallback is the existing Worker-generation respawn. The readout is the measured rate.
- **Favicon / title.** `tab-status.ts` draws the mark on a 32 px canvas → `link[rel=icon]` data URL (`img-src data:`); states idle / mining / won (60 s) / paused; title `▸ 18/min · 2/4 · Yacana`; both update while hidden; the loop stops drawing while hidden or under reduced motion.
- **Query overrides.** Today any `?miner=&token=` wins over storage (`packages/web-miner/src/config.ts:40`), so a crafted link could point a production page at a fake deployment on the allowed node. Overrides are honoured only when the build set `VITE_E2E_QUERY_OVERRIDES=1` AND `location.hostname === 'localhost'`; production ignores them. `?node=` stays restricted to the allowlist. E2E-only hooks (`window.yacana.simulateClaimFailure`) exist only in E2E builds.
- **Routing.** Three routes on `history` + `popstate` (~40 lines) instead of a router dependency.
- **CSV / JSON export.** `toCsv(rows)` → `Blob` → `URL.createObjectURL`; JSON serialises bigints as decimal strings. No server.
- **Withdraw.** The review step snapshots the parsed recipient, mode and amount (decimal string → `bigint` with the token's decimals; no floats) and the send uses the snapshot; amounts never touch OS notifications.
- **Node trust.** Every surface runs `assertDeployment` at boot (chain id, rollup version, miner address and class id against the build config); reads have timeouts, concurrency caps and size caps before any slot lookup; the docs say what the RPC sees (IP, timing, which reads, submitted transactions) and that it can censor, mislabel or stall but never steal.

### Trade-offs and alternatives not taken

- Per-claim timestamps from block bodies (codex: a full or incremental claim scan; fable: a bounded 64-block scan): rejected — needs Poseidon2 leaf-slot hashing in the browser and the owner accepted losing the histogram; fable's `getPublicStorageAt(block)` bisection is noted as a future WASM-free option.
- The demo as a same-origin `<iframe src="/mine/demo">`: rejected in favour of the shared Vite base — no per-path `frame-ancestors` exception, no iframe height sync, one headers block; the cost is the landing carrying the bb.js pipeline in a click-gated chunk.
- A pure-TS Poseidon2 for slot derivation: rejected (rolling our own hash); lazily loaded bb.js: rejected for the 3 MB cost at first paint; the slot table wins.
- Wallet-sdk integration for launch mode: rejected as scope creep; v1 links the CLI path (`bun run launch -- commit`); in-page wallet connection stays a roadmap item.
- Rotation (a second account per key after a lost race), by a second credential or by indexed derivation: **dropped by the owner**; the PXE-reset recovery replaces it, and the derivation keeps an index parameter for a later plan.
- A legacy-store migration: dropped as unreachable (new origin, first deploy at P4.2).
- Deploying and previewing from GitHub Actions with a Cloudflare token (any variant): **replaced by Cloudflare's Git integration at the owner's request** — no token in GitHub, production only from `main`, previews for every branch; the price is committing the compiled artifacts so Cloudflare's builder needs only Bun.
- `next-themes`: rejected; the repo's provider moves to `ui`. sqlite-opfs encrypted stores: deferred (roadmap). A router dependency: rejected for the 40-line hook.

Pass = exit 0, no skipped required spec, no new Biome suppressions. Every gate includes the fast layers for the touched packages; E appears on the phases that change behaviour a browser can observe. ## Security & Adversarial Considerations

- **Threat model.** Attackers: whoever serves the page (reads the unlocked master in memory during a session, redirects claims and withdrawals; stated on the page: run your own build), XSS in any of the three apps (one origin means one compromise reaches all three, the vault key and the RP ID), a malicious node (wastes work, mislabels stats, censors, stalls, sees IP and timing; never steals), a phisher of the twelve words, a malicious extension, a lost or stolen device, a compromised npm dependency, a PR that tries to publish a phishing page under the project's preview domain, a CPU-sink abuse of the demo, a second origin (`*.pages.dev`) confusing users.
- **Cryptography.** WebAuthn PRF (CTAP2 `hmac-secret`) through `navigator.credentials` only; HKDF-SHA256 and AES-GCM-256 through WebCrypto only; `@scure/bip39` pinned exactly to `2.3.0` as a direct dependency; Schnorr account keys through `@aztec/*` `5.2.0` only; field sampling by `fromBufferReduce` over 64 HKDF bytes (the repo's `secret.ts` pattern). Every label is versioned and pinned by golden vectors: changing one moves every user's address. PRF results must be exactly 32 bytes; short or missing results fail closed and offer the twelve words. Records are versioned (`v: 1`).
- **Keys at rest.** Default passkey mode: no spend secret at rest. Words and convenience modes: the sealed master under the device key, with the honest limit above. WalletDB in memory (no `sk`/`signingKey` on disk, verified against the wallet's source). The PXE store's residual is stated. Previews and the `pages.dev` alias never create keys; the hostname `yacana.network` is fixed (the production assembly refuses any other RP ID). A lost or reset passkey with no PRF sync strands the balance: the owner accepted this for testnet with an explicit warning and a move-funds nudge, to be revisited before mainnet.
- **Phrases.** Paste blocked on the quiz, `clipboard.readText` never called, drag-drop blocked on restore, hostname banner, the words replaced by dots in the DOM after the checkbox, inputs with autocomplete/autocorrect/spellcheck off (Chrome's enhanced spellcheck uploads field text), state cleared on unmount, no analytics, the phrase never touches storage or logs.
- **Inputs.** Addresses through `AztecAddress.fromString` (throws), non-zero, not self; amounts as decimal strings → `bigint`, ≤ balance, snapshotted at review; nonce 0 for self-calls; node URLs through `URL`, HTTPS outside E2E, within the allowlist that CSP enforces; query overrides only in E2E builds on `localhost`; mnemonics normalised (NFKD, single spaces, lowercase) and validated (12 words, checksum) before derivation; node-derived numbers validated (field widths, epoch ≤ open, claims ≤ N, response sizes) before slot lookups or rendering; `assertDeployment` at boot.
- **Frontend.** No `dangerouslySetInnerHTML`; React escaping; the CSP above (`script-src-attr 'none'`, `object-src 'none'`, `frame-src 'none'`, `frame-ancestors 'none'`, `base-uri 'none'`, `form-action 'none'`), CORP and Permissions-Policy; no cookies, no server, so no CSRF; CSV formula guard (incl. tab and CR); the OG image is static; `style-src 'unsafe-inline'` remains for Radix/Sonner inline styles (audited in P2.1: `style-src-attr` if the audit allows).
- **Withdraw.** Review step shows what will be public; public withdraw carries the amber warning; the recipient check is a warning about undeliverable notes, not a guarantee.
- **Demo.** One click, one proof, `max(1, min(4, cores − 1))` threads, timeout, terminated in `finally`; no key, wallet, PXE or network beyond `'self'` and the node; desktop only.
- **Supply chain / CI.** 7-day min-age (`bunfig.toml`), frozen lockfile, SHA-pinned actions and a digest-pinned actionlint image, `permissions: contents: read`; no Cloudflare token exists anywhere (Cloudflare builds from the repo itself); the committed artifacts are verified fresh by `contracts.yml` on every PR that can change them, and the toolchain pin test guards that job (its limit stated: it hashes bb, nargo, one WASM and the dependency heads, not the npm-backed `aztec compile` CLI tree; owning that install stays on the roadmap); `wrangler` pinned for local `pages dev`. Residual, stated: a preview is PR-controlled code under the project's own preview domain — acceptable while the owner is the only author; enable Cloudflare's preview access policy (Access-gated previews) if a collaborator joins.
- **Rename hazards.** The new origin starts empty (no legacy data to migrate); renamed env vars break local `.env` files (documented); `bun.lock` diff reviewed; the old Elixir Pages project is retired after the new origin is live (Ask 6).
- **Node trust.** Every surface names the node; a lying node can only mislabel, censor or stall; Verify cannot prove the RPC honest, and says so; the docs say what the RPC sees.
