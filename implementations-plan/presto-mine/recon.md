## The Presto side, as read

- **Headless server** (`packages/presto/server/src/main.rs`): `--port <n>` (needs `PRESTO_HOME`), `--allow-all` / `PRESTO_ALLOW_ALL=1`, `ALLOWED_ORIGINS=a,b`, `BB_BINARY_PATH`, `RUST_LOG`. HTTP only, default `127.0.0.1:59833`; **no HTTPS and no cert setup headless** (HTTPS 59834 is the desktop app's, `src-tauri/src/certs.rs`). Origin gating deny-by-default: localhost auto-approved, others via `ALLOWED_ORIGINS`; no popup headless (`prove_returns_403_without_popup_in_headless`). Confirmed on the homelab: the 1.1.1 binary started with `Origin gating enabled (deny-by-default): localhost auto-approved` and listened on `127.0.0.1:59833` (checksum `48f524b1…` matched). Release assets: `presto-server-<v>-{linux,macos}-{x86_64,arm64}.tar.gz` + `.sha256`; app 1.1.1 is the latest release (2026-09-08).
- **Presto's own CI** runs the headless binary through `.github/actions/start-headless-presto` (`--port`, `--allow-all`, `PRESTO_HOME`, polls `/health`) and points `BB_BINARY_PATH` at a sidecar `bb`: the shape to copy.
- **`@alejoamiras/presto-noir` 1.0.1** (published 2026-09-08 22:54 UTC): `PrestoUltraHonkBackend(acirBytecode, api, { bbVersion = '5.2.0', presto?, verificationKey?: { bytes, verifierTarget }, fallback: 'wasm' | 'none' = 'wasm', onPhase? })`; `generateProof(witness, { verifierTarget })` POSTs `/prove/ultra-honk` `{ bytecode, witness: base64, verifier_target, vk?: base64 }` and degrades to real WASM unless `fallback: 'none'`, which throws `PrestoUnavailableError { reason, phase? }`; `verifyProof` / `getVerificationKey` stay WASM; peer `@aztec/bb.js` exactly `5.2.0`; per-origin cap 4 → `429 origin_queue_full`; route since app 1.1.0. ## Dedup and collision risks

- Two Presto clients on one page (the page's `PrestoProver` for the banner and the Worker's backend) probe independently: the plan makes the Worker's `ready` message the source of truth for "native", the page's probe the source for the banner — never both for one fact.
- `quietNodeReads` and the node's `report()` must not see Presto traffic; the accelerator class has its own listeners.
- The e2e header mode already admits `http://127.0.0.1:*` and `http://localhost:*` (`packages/site/src/headers.ts:10,19`); production admits `https:` only — a headless (HTTP) Presto is an e2e device, never a production path.
