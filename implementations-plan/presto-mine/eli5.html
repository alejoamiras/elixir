Why this tier

Rubric: novelty low (you wrote Presto; its Noir kit slots in where the browser prover sits today), blast radius medium (the miner only; the wallet's proofs are untouched), irreversibility low, migration none, external coupling high (a local third-party process, its kit, its permission popups), security sensitivity medium (the page's request guard admits a fixed set of local addresses; Presto sees the circuit's witness, never your key). Human context

  • Why Presto never sees a secret. The work circuit's inputs are the domain, the seed, the epoch, a commitment to the miner and the nonce. The key that spends is not among them, and the prover is only ever handed those inputs, never the job. What Presto can do is notice that all the proofs of one session belong together.
  • Why the browser still checks the winning proof, and what that does not buy. A Presto that returns rubbish would make the miner think it won and then fail the claim; one check per win, against the miner's own inputs, keeps that off the chain. It cannot catch a Presto that quietly returns losing rubbish forever, or stalls: that shows up only as a dead rate. Binding a local port is a weaker capability than controlling your browser, so Presto is treated as untrusted throughout.
  • Why a first native proof, not a connected Presto, lights the ✦. Building the connection proves nothing; the first proof that actually comes back does. Before that the pill says nothing about Presto.
  • Why headless Presto is a test device, not a production path. The headless server speaks plain http on the loopback address and has no encrypted mode. The shipped page only talks https, and Presto's kit defaults to https in a browser. The test build admits the plain local port; a config test builds production with hostile test settings and finds none.
  • Why versions matter. Presto proves with the exact bb version the page asks for (the miner is pinned to Aztec 5.2.0). Today's Presto ships that version; when Presto moves ahead, it downloads 5.2.0 once, checksum verified, and keeps it. The test rig tells the headless server which version it is so it never downloads anything in CI, and the run checks that it did not.
  • Why the threads slider greys out. While Presto is the prover, the browser's thread count changes nothing: Presto's own speed setting, in its app, decides how many threads its bb uses. The slider saying otherwise would lie, so it points there instead.
  • Why "Presto needs an update" is rare. Presto downloads whatever bb version a page asks for, so a version difference is never an error, only a one-time download. That row appears only for a Presto too old to serve this kind of proof at all.
  • Why the billboard cannot carry the fix-it states. Presto's billboard renders only "missing" and "present" by design, and has no Retry of its own; the states that need a hint belong to Presto's ribbon. Rather than two Presto surfaces on one page, the miner draws those hints in its own row, in Presto's words.
  • Why the seven-day rule bites. The repo refuses any npm package younger than seven days, a guard against poisoned releases. Presto's kit was published yesterday and the banners today. The exception Bun offers is by package name, for every future version too, so it is a lasting decision, not a one-off.

What the reviewer said

Codex (GPT-6 Astra, one pass at high, read-only, both repos) returned rework: the shape was right, the plan was not yet buildable. Its material corrections, each checked against the source and folded in:

  • The guard admitted one address; Presto's kit uses several. The health check and the proof route are different addresses, in http and https flavours. The guard now admits the fixed set derived from one config, and refuses a node configured at any of them.
  • The fallback was designed in the wrong place. The mining loop holds its prover for a whole run of nonces, so swapping the worker's prover from outside would miss the running job or repeat nonces. The swap now happens inside the prover itself, on the same witness, using the kit's own "force local" switch.
  • "Busy" is not a retry in the kit. A busy Presto is an immediate fallback; the plan now gives it three chances across nonces before sticking to the browser.
  • The old rule would have refused a healthy Presto that merely had to download a version. Removed; the download is a phase the row explains.
  • The ✦ would have lit on connection, not on proof. Now it lights after the first native proof.
  • The winning check has to use the miner's own inputs, not what Presto says they were, and the miner has to re-check that nobody pressed Stop while it was verifying.
  • The billboard has no Retry button; Start and the row's Retry are the way back.
  • CI would have downloaded bb from GitHub every run (found independently before the audit landed) and killed Presto in a way that orphans its child process; both fixed.
  • Two claims in the security section were wrong: "a lying Presto costs one proof" and "whoever owns the machine owns the browser". Both rewritten with the honest residuals.
  • Smaller dependency: the page's health check uses the core kit, not the full one that drags the Chonk prover in.

Nothing was rejected outright. The full transcript and the 32-row verification ledger are in audit-codex.md.
